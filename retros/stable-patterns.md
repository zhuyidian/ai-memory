## 候选条目

### 模式
- 标题：显式资产主导、runtime 最小补缺
- 结论：当排序逻辑长期依赖 runtime 硬编码补丁时，应把排序信号迁移到离线生成的显式资产，runtime 仅做缺项兜底。这样排序可解释、可回归、可审查。
- 适用范围：候选排序信号需要独立于加载顺序的 IME 场景
- 不适用范围：排序逻辑完全由用户行为实时驱动的场景（如学习排序权重）
- 来源项目：V5.0-Input / task 73
- 是否已升级：否，仅在本项目验证一次

### 模式
- 标题：纯简拼长词扩展映射 top-N 是否够用
- 结论：每位首字母只扩展 top-2 高频音节，如果目标词对应音节不在 top-2 里会漏召回。top-3 能覆盖更多但路径数从 32 涨到 243。当前 top-2 是保守限流，尚未在真机上验证覆盖率和首候选命中率。
- 适用范围：纯简拼长词组合兜底链路
- 不适用范围：已有精确 initials 匹配的场景（走 INITIALS_PHRASE，不涉及扩展）
- 来源项目：V5.0-Input / task 84
- 是否已升级：否，真机体验未验证

### 模式
- 标题：纯简拼长词兜底触发范围与阈值
- 结论：4-6 位触发、mergedCandidates < 4 时触发。4 位以下走现有 initials 精确匹配，7 位以上组合空间过大。阈值 < 4 是为了避免在已有足够结果时引入低质量组合噪音。但这两个参数都未经真机验证调优。
- 适用范围：纯简拼长词组合兜底链路
- 不适用范围：全拼、混拼、有精确匹配的场景
- 来源项目：V5.0-Input / task 84
- 是否已升级：否，真机体验未验证
