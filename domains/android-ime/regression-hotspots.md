# Android 输入法高风险回归点

## 适用范围
- 适用于 Android 输入法项目
- 用于实现前、评审前、回归测试前

## 核心立场
- 输入法最危险的不是“编不过”，而是“能弹出来但行为悄悄错了”。
- UI 改动和输入行为改动，都会跨层打穿主链路。
- 每次改动都要优先检查高频回归点，而不是只看当前需求是否表面成立。

## 重点回归区域

### 1. 拼写中的文本同步
- 拼写中的文本没同步到宿主输入框
- 拼写中的文本清空时机错误
- 选词后拼写中的文本未清掉
- 删除键对拼写中的文本和已提交文本的优先级错误

### 2. 候选流转
- 候选栏显示条件错误
- 选词后候选没刷新或刷新过度
- 快捷数字与可见候选不同步
- 候选分页状态与实际内容不同步

### 3. 回车与编辑器动作
- 单行输入框错误提交换行
- 编辑器动作没触发，或者被误吞
- 多行输入框被错误走单行回车兜底
- 没有宿主动作时缺少兜底逻辑

### 4. 删除行为
- 有拼写中的文本时误删已提交文本
- 有选中文本时没优先删选区
- 表情或代理对字符删除不完整
- 长按删除节奏不稳或状态泄漏

### 5. 模式切换
- 中英切换后状态未重置
- 符号 / 数字 / 字母切换后回退模式错误
- 大小写状态在模式切换后残留
- 进入符号模式后分类、分页状态没复位

### 6. 宿主输入上下文兼容
- 不同输入框类型下默认键盘模式错误
- 电话 / 数字 / 密码场景行为不一致
- 选区更新后拼写中的文本没及时清理
- 宿主焦点切换后旧状态残留到新输入框

### 7. UI 与状态同步
- 状态变了但键盘没刷新
- 候选栏和键盘主体显示不同步
- 特殊键视觉态和真实状态不一致
- 顶栏 / 候选栏 / 标识图 / 右侧功能列只对齐了视觉，没对齐交互

### 8. 符号与数字布局
- 切页后键区没更新
- 分类切换后页码没重置
- 固定功能列混入主键区
- 返回字母模式的目标模式错误

## 稳定评审清单
- 拼写中的文本是否总能和宿主保持一致
- 候选显示、选择、清空是否闭环
- 删除是否按“拼写中的文本 -> 选区 -> 普通文本”的优先级执行
- 回车是否按“多行 / 编辑器动作 / 兜底”走正确路径
- 模式切换后是否有旧状态残留
- UI 的焦点态、按压态、选中态是否与真实状态一致
- 不同输入框类型是否仍然符合预期

## 最小验证集
- 英文输入
- 中文拼写 + 选词
- 删除键普通点按
- 删除键长按
- 单行回车
- 多行回车
- 模式切换
- 符号 / 数字键盘进入与回退
- 宿主选区变化后的拼写清理

## 不适用场景
- 当前项目不是输入法或输入面板类系统
- 当前问题纯粹是词库数据清洗，不涉及输入主链路

## 来源
- Android 输入法项目中高频复发问题
- 在宿主适配、候选同步、UI 重构中反复出现
