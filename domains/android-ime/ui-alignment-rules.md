# Android 输入法 UI 对齐规则

## 适用范围
- 适用于 Android 输入法项目中的 UI 对齐、参考图还原、视觉重构类任务
- 适用于键盘顶栏、候选栏、键区、功能列、底部承载区等布局设计

## 核心立场
- 输入法 UI 对齐不是简单改几个边距，而是重建稳定的空间关系。
- 视觉对齐必须服从输入行为，不允许为了贴图把交互打坏。
- 好的输入法 UI 任务，目标不是“像图”，而是“结构关系稳定、交互不回归、局部可维护”。

## 稳定规则
- 顶栏、候选栏、键区、底部区必须有明确层次，不混成一个视觉块。
- 固定占位元素必须先建结构，再调尺寸。
- 滚动元素和固定元素必须明确谁占位、谁滚动。
- 功能键要和普通字符键保持视觉层次差异。
- 焦点态、按压态、选中态不能完全等价。
- 视觉升级不应回退到旧的容器模型或旧的交互模型。

## 推荐布局关系

### 1. 顶栏
- 顶栏是独立承载层，不是键区的一部分。
- 顶栏内的左侧区、候选区、右侧区应该语义清楚。
- 顶栏高度应稳定，不随内容轻易抖动。

### 2. 候选区
- 候选区是状态驱动的可见内容区，不是随意堆控件的位置。
- 候选滚动区应有固定起始和结束边界。
- 空态、拼写反馈、符号分类标签要共享同一语义容器。

### 3. 固定占位元素
- Logo、右侧功能列、固定返回键等都属于固定占位元素。
- 固定占位元素必须先锁定宽高和位置关系，再让动态内容围绕它们布局。
- 动态内容不能视觉侵入固定占位区。

### 4. 键盘主体区
- 键区是独立主区域，和顶栏、底部区有清晰分界。
- 普通字符键与功能键应该有明确视觉分层。
- 横向和纵向间距要统一，不做局部手工补丁式对齐。

### 5. 底部区
- 底部承载区要有完整结构，不通过“露底色”假装完成。
- 如果参考图有独立底部层，应该通过真实承载布局实现，而不是只改背景色。

## 候选栏对齐规则
- 先定义候选区的可滚动边界，再定义条目的内边距。
- 有 Logo 时，Logo 固定不滚动，候选内容在其左侧滚动。
- 候选栏左右间距在滚动时仍要保持，不能只在初始位置成立。
- 如果顶栏有多个内容模式，所有模式都应遵守同一占位规则。

## 特殊键规则
- 删除、回车、大小写、翻页键、返回键应视为功能键，不应继续伪装成普通字符键。
- 功能键的背景、图标、尺寸、反馈要与字符键区分开。
- 长按、重复触发、模式态反馈需要与视觉态一致。

## 视觉反馈规则
- 焦点态用于可导航性
- 按压态用于即时反馈
- 选中态用于持久状态
- 这三者可以相似，但不能完全复用同一表现

## 参考图使用规则
- 参考图用于提取结构关系、节奏、层次，不用于逐像素照搬。
- 若参考图和当前项目组件体系冲突，优先保留现有项目体系中的可维护方案。
- 若参考图要求与当前交互语义冲突，优先保留交互正确性。

## 常见反模式
- 只改数值，不改结构关系
- 只对齐静态截图，不检查滚动、焦点、点击、长按
- 固定元素和滚动元素没有明确边界
- 为了追参考图引入一套和项目风格完全不兼容的视觉体系
- 用单独的特判把每一种模式拼凑出来，没有统一布局语义

## 推荐任务边界
- UI 对齐任务默认只改：
  - 视图层
  - 布局文件
  - drawable 资源
  - 必要的渲染状态
- 不顺手扩散到：
  - 词库
  - 排序逻辑
  - 宿主绑定
  - 设置页

## 评审清单
- 是否先建立了稳定占位关系
- 滚动和固定元素是否分工明确
- 顶栏 / 键区 / 底部区是否分层清晰
- 功能键与字符键是否层级分明
- 视觉态是否和真实状态一致
- 关键输入行为是否仍然正常

## 什么时候用
- 参考图对齐任务
- 候选栏 / Logo / 顶栏关系调整
- 符号键盘、数字键盘、特殊键视觉改造

## 不适用场景
- 当前任务纯粹是词库、排序、匹配器逻辑
- 当前问题不涉及 UI 结构或视觉层次

## 来源
- 输入法类 UI 改造任务中，顶栏、候选栏、固定占位和键区关系反复出现的稳定规律
- 多次参考图对齐任务后沉淀的布局原则
