# 工作流模板：最终自检清单

## 用途
- 这份模板用于生成项目内 `workflows/review_checklist.md`。
- 目标是让 agent 在任务结束前按项检查，而不是只说“看起来没问题”。

## 模板正文

```md
# REVIEW CHECKLIST

每个任务结束前，必须按此清单完成最终自检。
不要只说“看起来没问题”，要按项检查。

---

## 1. 作用域检查
确认：
- 是否只修改了允许的 module 和文件
- 是否误改了其他 module
- 是否误改了根工程配置
- 是否存在未说明的越界修改

---

## 2. 编译检查
确认：
- 是否有 unresolved reference
- 是否有 import 错误
- 是否有类型不匹配
- 是否有缺少类 / 方法 / 字段
- 是否有 build 配置问题

---

## 3. 资源与配置检查
确认：
- 是否有资源缺失
- 是否有布局 id 不一致
- 是否有字符串 / 颜色 / 主题缺失
- 是否有 XML 引用错误
- 是否有 Manifest 配置缺失或错误

---

## 4. 功能检查
确认：
- 是否满足任务文件中的核心功能要求
- 是否存在未接线逻辑
- 是否存在只写了 UI 没写逻辑
- 是否存在只写了逻辑没接到 UI
- 是否存在明显遗漏的边界行为

---

## 5. 稳定性检查
确认：
- 是否有明显空指针风险
- 是否有生命周期错误
- 是否有状态不同步问题
- 是否有明显崩溃风险
- 是否有异常流程未处理

---

## 6. 规范检查
确认：
- 是否遵守了指定 skill
- 是否尽量遵守当前项目与目标 module 风格
- 是否引入了不必要的新架构
- 是否有明显风格漂移
- 是否有不必要的大范围重构

---

## 7. 完整性检查
确认：
- 是否仍存在 TODO / FIXME / 伪代码
- 是否仍存在占位实现
- 是否仍存在引用不存在的类或资源
- 是否仍存在半成品逻辑

---

## 8. 交付检查
最终输出必须包含：
1. 修改文件列表
2. 每个文件作用
3. 是否影响其他 module
4. 编译 / 运行方式
5. 使用方式
6. 已知限制
7. 风险说明
```
