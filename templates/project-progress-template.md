# 项目任务进度模板

## 用途
- 这份模板用于生成每个项目的 `tasks/progress.md`。
- 目标是把“当前只能做哪一张 task、哪些已经完成、执行入口是什么”固定成一个调度页。
- 它是执行阶段的调度页，不替代具体 task 文档。
- 它只指向当前 task，不承载 scope、非目标、验收标准或新增需求。

## 适用场景
- 新项目初始化
- 项目任务开始变多，需要一个单入口管理当前任务时
- `CC_NEXT` 在生成项目骨架时作为参考模板使用

## 模板正文

```md
# 当前任务进度

---

## 执行规则（必须遵守）

### 1. 必须先阅读以下文件
- `AGENTS.md`
- 当前要进行的任务（`tasks/*.md`）
- `workflows/task_breakdown.md`
- `workflows/implementation.md`
- `workflows/review_checklist.md`

---

### 2. 当前任务只遵守指定 skill
- `<skill_name>`

---

### 3. 已完成任务
- `<已完成任务 1>`
- `<已完成任务 2>`
- `<已完成任务 3>`

---

### 4. 当前要进行的任务
- `<当前任务文件名>`

---

### 5. 指定 module
- `<module_name>`

---

### 关键规则
- 当前任务只能有一个
- 当前 task 正文是 scope、非目标、验收标准和修改边界的唯一来源
- `progress.md` 不能补写或改写当前 task 的需求内容
- 禁止执行“已完成任务”
- 禁止重新执行 baseline 或已关闭的初始化任务
- 如果需要开启下一张任务，必须先完成当前任务的交付与复盘
```

## 使用说明
- `progress.md` 只负责指向“当前做哪一张 task”，不负责展开任务细节。
- 已完成任务列表用于防止 agent 回头重做旧任务。
- 当前任务变更时，应优先更新 `progress.md`，再开始新一轮执行。
- 如果项目很小，已完成任务可以先只有 1 到 2 条，但“当前任务只能有一个”这条规则应始终保留。

## 推荐搭配
- 搭配 `AGENTS.md` 使用，约束执行边界
- 搭配 `workflows/` 使用，约束执行方法
- 搭配项目 `memory/` 使用，沉淀项目专属稳定知识

## 不要这样做
- 不要把 task 全文复制到 `progress.md`
- 不要把 task 的 scope、非目标、验收标准写到 `progress.md`
- 不要在 `progress.md` 里同时列多个当前任务
- 不要把全局方法论写满 `progress.md`
- 不要任务还没交付就切换当前任务
