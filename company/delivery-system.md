# 交付系统

## 记忆状态
- 状态：active
- 替代文件：无
- 上次复核：2026-04-30
- 下次复核触发条件：当交付产物、质量线或复盘升级规则变化时复核

## 适用范围
- 适用于所有商业项目
- 用于统一“从需求到交付再到复盘”的工作闭环

## 生命周期来源
- 项目阶段顺序以 `company/project-lifecycle.md` 为唯一主文档。
- 本文件只定义交付系统的原则、产物质量线和记忆升级规则。
- 如果本文件与 `company/project-lifecycle.md` 对阶段顺序的描述冲突，以 `company/project-lifecycle.md` 为准。

## 交付原则
- 项目不是靠一次对话做成的，而是靠稳定流程做成的。
- 每个阶段都要有明确产物。
- 当前执行阶段只有一个事实来源，避免双轨文档体系。

## 执行期裁决规则
- 当前 task 正文是实现阶段的唯一事实来源。
- `tasks/progress.md` 只负责指向当前 task 文件名和执行状态。
- scope、非目标、验收标准、允许修改范围和禁止修改范围只能由当前 task 正文定义。
- `AGENTS.md` 和 `workflows/` 只约束执行方式，不能补写需求。

## 交付系统规则
- 需求收敛、任务规划、实现等阶段顺序只引用 `company/project-lifecycle.md`。
- 本文件只保留验证、交付、复盘、记忆升级和质量线相关规则。

### 验证
- 必须有明确验证入口
- 优先跑稳定、可重复的本地验证链路
- 无法验证时，必须明确说明阻塞原因
- 不用“看起来没问题”替代验证

### 交付
- 交付必须包含：
  - 修改范围
  - 修改结果
  - 验证方式
  - 已知风险
  - 使用说明或回归说明
- 不只汇报“做了什么”，还要汇报“怎么确认它成立”

### 复盘
- 复盘不写成长流水账
- 只提炼：
  - 稳定有效的打法
  - 容易复发的问题
  - 可模板化的流程
- 一次性经验不升级为全局记忆

## 记忆升级规则
- task 内临时结论留在 task
- 项目专属稳定知识进入项目 `memory/`
- 跨项目稳定知识进入 `E:\project\ai-memory`
- 必须长期遵守的规则进入 `AGENTS.md` 或团队规范文件

## 复用规则
- 优先复用：
  - task 模板
  - 验证清单
  - 交付清单
  - 领域稳定打法
- 不复用客户特有信息
- 不把项目细节误升级为公司方法论

## 质量线
- 作用域受控
- 主链路闭环
- 验证路径明确
- 输出可交付
- 风险说明真实
- 复盘能反哺下一单

## 什么时候用
- 新项目启动
- 当前项目进入实现前
- 交付前检查
- 项目复盘时

## 不适用场景
- 当前只是局部代码问题，且已有项目内 workflow 约束
- 当前项目已有更严格的任务执行规程时，应以项目规程为准

## 来源
- 面向可收费、可复制交付项目的长期工作模式
